# 技術調査と設計判断

作成日: 2026-09-16。Spec Kitの計画手順に従い、限定した調査エージェントで公式資料を確認。
依存版は実装開始時に相互互換性を確認して固定する。

| 決定 | 理由・代替 | 根拠 |
| --- | --- | --- |
| TypeScript＋Vite | 64マスと限定画面をDOMで扱う。React等の依存は不要。型検査をビルドとは別に実行 | [Vite](https://vite.dev/guide/)、[機能](https://vite.dev/guide/features) |
| Vitest | 純粋関数を検証しViteと設定共有。Node標準テストより開発設定を統一しやすい | [公式](https://vitest.dev/guide/) |
| Playwright | 回帰検証、Chrome/Edgeチャンネル、Firefox。手動確認も残す | [対応ブラウザ](https://playwright.dev/docs/browsers) |
| Web Worker | AI探索をUIから隔離。メインスレッド分割実行より応答を確保しやすい | [HTML標準](https://html.spec.whatwg.org/multipage/workers.html) |
| Web Audio | 短い効果音を生成。音声素材ファイル不要。ユーザー操作で開始・再開 | [W3C仕様](https://www.w3.org/TR/webaudio/) |
| localStorage | 20件の結果と設定だけを保持。IndexedDBを必要とする規模ではない | [HTML標準](https://html.spec.whatwg.org/multipage/webstorage.html) |

## 仕様から導く実装規則

- 予約回数は確認時に消費し、失効しても戻さない。未確定キャンセルは消費しない。
- 同じマスへの双方予約は空きマス規則から許容し、手番順に解決する。後の予約は変化後の盤面で判定する。
- 終局判定を予約解決より先に行う。満盤・双方合法手なしなら待機予約を失効し結果を一度だけ保存する。
- 通常合法手なし・予約残数0なら自動パス。通常合法手がある場合は自発パス不可。
- 先手と色は別に抽選。再現対局では盤上の開始色を保持し、操作プレイヤーの先後と色割当を両方交換する。
- 固定シードは開始条件の再現用。時間制限AIの全手順一致を保証しない。
- 対局中イベント表示と保存する結果20件を分離。進行中対局の永続化は追加しない。

## 品質上のリスク

予約は2手番を要し、通常の合法手がなくてもパスできる。AIが予約を選ばなくなる可能性は未検証。
T041で通常手のみとの比較と予約が有利な固定局面を調査し、証拠なく「戦略的価値あり」としない。
開始配置は8種類・4石を維持し、各色2石、対称性、双方合法手、回転反射による重複を確認する。
候補の完成度と先手差はT021/T041で測定する。ルール・候補数の変更は利用者への確認対象。
